# 참가자 개인정보 처리 고지문 (템플릿)

> ⚠️ **법무/개인정보 전문가 검토 필수.** 이 문서는 제품이 **실제로 수집·처리하는 데이터 항목**을 코드 기준으로 정확히 기술한 골격 템플릿이다. 개인정보보호법(PIPA)상 고지 의무 항목·문구·미성년자 법정대리인 동의의 구체 요건은 **작성자가 법률 전문가가 아니므로 확정하지 않았다.** 실제 워크숍에 사용하기 전, 아래 `[검토 필요]` 표시 항목을 반드시 전문가 검토로 채워야 한다.

---

## 1. 수집하는 데이터 (제품 코드 기준 — 사실)

이 워크숍 도구가 실제로 저장하는 항목은 다음과 같다. (근거: DB 스키마 `db/migrations/0014_deliberation_core.sql`, 세션 설정 `sessions.metadata.privacy_settings`)

| 항목 | 저장 위치 | 내용 | 개인 식별성 |
|---|---|---|---|
| 표시 별칭(alias) | `participants.display_alias` | 화면에 보이는 이름/별명. 운영자가 부여하거나 참가자가 입력. | 기명 모드에서 식별 가능 |
| 익명 핸들 | `participants.anon_handle` | 익명 모드용 임의 핸들. | 익명 모드에서 비식별(단, N이 작으면 사실상 식별 가능 → §4) |
| 입장 키 연결 | `participants.access_key_id` | 참가자 1인 ↔ access key 1개 연결(중복 입장·표 위조 방지용). | 간접 식별자 |
| 발언 본문 | `statements.body` | 참가자가 제출한 의견 텍스트. | 내용에 따라 식별 가능성 있음 |
| 투표 | `statement_votes` (agree/disagree/pass) | 발언별 개인 투표. **개인 표 원자료는 운영자에게도 노출되지 않으며(집계 함수로만 조회), 리포트에도 담기지 않는다.** | 개인 표는 시스템상 비노출 |
| 집계 결과 | `landscape_snapshots.payload` | 발언별 찬반유보 **집계값만**. 개인 표 없음. | 비식별(k-익명 억제 적용) |
| 모더레이션 기록 | `moderation_events` | 신고/숨김/복원 등 처리 로그(행위자 역할·사유). | 운영 감사용 |
| 프라이버시 설정 | `sessions.metadata.privacy_settings` | 익명 여부·공개범위·보관기간·사전동의 확인·**녹음 동의 여부와 동의 시각**·미성년 세션 여부. | 설정 메타데이터 |
| **음성 전사 텍스트** | `transcript_sources` / `transcript_segments` / `transcript_insights` | **테이블(분임) 단위 논의의 음성을 텍스트로 전사한 내용.** 기기 라벨·테이블 라벨·시간 구간·전사 텍스트. | 발언 내용에 따라 식별 가능성 있음(개인 화자 태깅은 하지 않음) |

**녹음·전사 수집 여부는 세션 설정이다 (사실):** `privacy_settings.recordingConsent`가 확정된 세션에서만 전사가 수집된다. 이 값이 없으면 서버가 전사 데이터 수집을 거부한다(기술적 게이트).

**수집하지 않는 것 (사실):**
- 개인 투표의 개별 원자료를 운영자·리포트에 노출하지 않는다(집계·플래그만).
- **화자분리(누가 말했는지)를 하지 않는다.** 전사는 테이블 단위이며, 스키마의 `speaker_tag`는 개인이 아니라 테이블 라벨('T3')이다.
- **원음성(오디오 파일)은 서비스 서버에 저장하지 않는다.** 전사는 현장 기기에서 수행되고, 서버로는 텍스트만 전송된다. DB 스키마에 오디오 경로·파일명 컬럼 자체가 없다.
- 얼굴/영상은 수집하지 않는다.
- 별칭/핸들 외의 법정 신원정보(주민등록번호·연락처 등)는 이 도구가 요구·저장하지 않는다.

## 1-2. 녹음·전사 고지와 동의 절차 (사실 + [검토 필요])

**수집 항목**: 테이블(분임) 단위 음성 → 텍스트 전사. 화자 개인은 식별하지 않는다.
**목적**: 테이블별 논의 요약 작성, 워크숍 기록·절차 증빙. AI가 만든 요약은 **초안**이며, 퍼실리테이터 승인 없이는 결과물에 반영되지 않는다.
**보관기간**: 전사 텍스트는 기본 **7일**(발언·투표 데이터보다 짧게), 원음성은 워크숍 종료 후 **현장 기기에서 24시간 내 자동 삭제**. 상세는 `docs/data-retention-policy.md`.

**동의 절차 (운영 규칙):**
1. **사전 고지** — 워크숍 안내·초대 시점에 녹음·전사 수집 사실, 목적, 보관기간, 미동의 시 대안을 알린다.
2. **현장 명시 동의** — 시작 시 §7-2의 고지 문구를 낭독하고 동의를 확인한다. 운영자는 워크숍 설정에서 **녹음·전사 동의 토글**을 켜야 하며, 이 확인 없이는 서버가 전사 수집을 거부한다.
3. **미동의자 처리** — 동의하지 않는 참가자가 있으면 **(a) 해당 테이블을 녹음하지 않거나, (b) 녹음 구역 밖 좌석으로 안내**한다. 미동의자가 있는 테이블의 마이크는 켜지 않는다. 미동의를 이유로 워크숍 참여 자체를 제한하지 않는다.
4. **상시 표시** — 녹음 중인 세션은 참가자 화면과 운영자 콘솔에 "이 세션은 녹음 중입니다" 배너가 상시 표시된다(끌 수 없음).
5. **철회** — 진행 중 언제든 녹음 중단을 요청할 수 있고, 요청 시 해당 테이블 녹음을 중단한다.

- [검토 필요] PIPA상 음성정보 수집·이용 동의의 형식 요건(서면/전자/구두 동의의 유효성, 증빙 보관 방법), 별도 동의 분리 여부.
- [검토 필요] 미성년자 세션에서 녹음·전사 동의를 법정대리인 동의와 어떻게 결합할지.

## 2. 수집 목적 (사실 + [검토 필요])

- 워크숍 참여(발언·투표) 운영 및 진행.
- 합의점·쟁점·소수의견 **집계 결과판** 생성.
- 절차 증빙(누가 아니라 "어떤 절차로 결론이 도출됐는가")을 위한 운영 로그.
- **(녹음 동의 세션) 테이블별 논의 요약·워크숍 기록 작성.** 발언자 개인 귀속이 아니라 테이블 단위 논의 정리가 목적이다.
- [검토 필요] 위 목적을 넘어서는 2차 이용(연구·홍보·외부 제공 등)이 있다면 별도 고지·동의가 필요한지 전문가 검토.

## 3. 보관 및 삭제 (사실 + [검토 필요])

- 보관기간은 세션 설정(`privacy_settings.retentionDays`)에 지정한 기간을 따른다. 파일럿 기본값은 30일.
- **전사 텍스트는 기본 7일**(발언·투표보다 짧게) 후 삭제한다.
- **원음성은 서비스에 저장되지 않으며**, 현장 기기의 임시 음성 파일은 워크숍 종료 후 **24시간 내 자동 삭제**하고 삭제 로그(텍스트)로 증빙한다.
- 삭제 절차·접근권한·삭제 증빙은 `docs/data-retention-policy.md`를 따른다.
- [검토 필요] PIPA상 보관기간 상한, 파기 방법·증빙 의무의 구체 요건. 음성·전사 자료의 별도 보관 요건 포함.

## 4. 익명성의 범위 (사실 — 솔직 고지)

- 익명 모드에서도 **참가자 수가 적으면 사실상 익명이 보장되지 않는다.** 제품은 이를 두 층위로 방어한다:
  - **N<12이면 익명 모드 자체가 비활성**된다(기명 또는 무기록 토의로 안내).
  - 표가 너무 적은 발언은 **k-익명 억제**로 집계 수치가 마스킹되어 결과판·랭킹에서 제외된다.
- 따라서 "익명"은 "인원·표본이 충분할 때 개인 표를 역추론하기 어렵다"는 의미이지, 절대적 비식별을 보장하는 것은 아니다. 참가자에게 이 한계를 있는 그대로 고지한다.

## 5. 참가자 권리 (운영 규칙 + [검토 필요])

운영 규칙으로 보장하는 것:
- **열람 요청**: 참가자는 자신이 속한 테이블의 전사 텍스트와 그로부터 만들어진 요약을 운영자에게 요청해 확인할 수 있다.
- **삭제 요청**: 특정 발언·구간의 전사 삭제를 요청할 수 있고, 운영자는 요청 구간을 삭제한 뒤 삭제 기록을 남긴다.
- **녹음 중단 요청**: 진행 중 언제든 해당 테이블의 녹음 중단을 요청할 수 있다.
- 요청 창구(담당자·연락처)는 각 워크숍 고지문에 기입한다.

- [검토 필요] 열람·정정·삭제·처리정지 요구권의 구체 범위와 행사 방법(익명 데이터·테이블 단위 전사는 본인 특정이 불가할 수 있음 → 권리 행사 방식이 달라질 수 있음).
- [검토 필요] 동의 철회 시 이미 집계·요약에 반영된 데이터의 처리 방식.

## 6. 미성년자 세션 ([검토 필요] — 특별 주의)

> ⚠️ 미성년자가 포함된 워크숍(예: 청소년 포럼·학교·교회 청년부 등)은 별도 법적 요건이 있다.
- 제품은 미성년 세션 플래그와 법정대리인 동의 확인(`privacy_settings.minorConsent`)이 확정되지 않으면 세션 시작을 서버에서 거부한다. **이는 기술적 게이트일 뿐, 법적 유효성을 보장하지 않는다.**
- [검토 필요] 법정대리인 동의의 유효 요건(연령 기준·동의 방식·증빙 보관), 동의 문구, 학교/기관 승인 절차 — **전문가 검토 없이 확정하지 말 것.**

## 7. 고지·동의 확인 (현장 사용 문구 예시)

> 아래는 §1의 실제 수집 항목에 근거한 **초안 문구**이며, PIPA 문구 적합성은 [검토 필요].

### 7-1. 공통 문구 (모든 세션)

"본 워크숍에서는 여러분이 남긴 **별칭/익명 핸들, 발언 내용, 찬반·유보 투표**가 수집됩니다. 개인별 투표는 운영자도 볼 수 없으며 집계로만 사용됩니다. 데이터는 **○○일** 후 삭제됩니다. 익명 모드라도 인원이 적으면 개인이 드러날 수 있어, 그런 경우 수치를 가리거나 익명을 끄고 진행합니다. 동의하시면 입장 QR로 참여해 주세요."

### 7-2. 녹음·전사 문구 (녹음 동의 세션에서만 추가 낭독)

"이 워크숍에서는 **테이블별 논의를 녹음해 텍스트로 전사**합니다. **누가 말했는지는 기록하지 않으며**, 테이블 단위 논의 요약과 워크숍 기록에만 사용합니다. **음성 파일은 이 방의 기기를 벗어나지 않고**, 워크숍이 끝나면 24시간 안에 자동 삭제됩니다. 전사된 텍스트는 **○일** 후 삭제됩니다. AI가 만든 요약은 초안이며, 진행자가 확인한 내용만 결과물에 들어갑니다. **녹음을 원하지 않으시면 지금 알려주세요 — 그 테이블은 녹음하지 않거나, 녹음하지 않는 자리로 안내해 드립니다.** 참여 자체에는 아무 제한이 없습니다. 진행 중에도 언제든 중단을 요청하실 수 있습니다."

- [ ] 위 문구를 세션 설정(보관기간·익명 여부·녹음 동의 여부)에 맞게 채운다.
- [ ] 녹음 세션이면 워크숍 설정에서 **녹음·전사 동의 토글**을 켜고(서버 게이트), 미동의자 좌석·테이블 배치를 시작 전에 확정한다.
- [ ] 미성년자 세션이면 법정대리인 동의 문구를 [검토 필요] 항목 확정 후 별도 사용.
