# 데이터 보관·삭제 정책

> ⚠️ **법무/개인정보 전문가 검토 필수.** 이 문서는 제품이 **실제로 저장하는 데이터와 그 삭제 경로**를 코드 기준으로 기술한 운영 정책 골격이다. 보관기간 법정 상한·파기 의무·접근통제의 법적 요건은 작성자가 법률 전문가가 아니므로 확정하지 않았다. `[검토 필요]` 항목은 반드시 전문가 검토로 채운다.

---

## 1. 대상 데이터와 저장 위치 (사실)

근거: `db/migrations/0014_deliberation_core.sql`, `0015_delib_hardening.sql`, `sessions.metadata.privacy_settings`.

| 데이터 | 테이블 | 삭제 연쇄(cascade) |
|---|---|---|
| 세션 | `sessions` | 세션 삭제 시 아래가 연쇄 삭제됨 |
| 참가자 | `participants` | `session_id` FK `on delete cascade` |
| 그룹/배정 | `workshop_groups`, `group_memberships` | 세션·참가자 삭제 시 연쇄 |
| 라운드 | `workshop_rounds` | 세션 삭제 시 연쇄 |
| 발언 | `statements` | 세션 삭제 시 연쇄 |
| 투표 | `statement_votes` | 발언·참가자 삭제 시 연쇄 |
| 집계 스냅샷 | `landscape_snapshots` | 세션 삭제 시 연쇄 (집계값만, 개인 표 없음) |
| 모더레이션 로그 | `moderation_events` | 발언 삭제 시 연쇄 |
| 입장 키 | `access_keys` | 세션 삭제 시 연쇄 |
| 액션 감사 로그 | `action_ledger`(리포트 export 등 기록) | [검토 필요] 보존기간·삭제 정책 별도 판단 |
| 전사 소스(테이블↔기기 매핑) | `transcript_sources` | `session_id` FK `on delete cascade` |
| 전사 텍스트 세그먼트 | `transcript_segments` | 소스 삭제 시 연쇄 |
| 전사 기반 논거 초안 | `transcript_insights` | 세션 삭제 시 연쇄 |
| **원음성(wav)** | **DB 아님 — 현장 전사 기기 로컬 디스크** | 세션 삭제와 무관. 아래 §2-2 별도 절차 |

**설계상 사실:** 세션(sessions) 한 건을 삭제하면 참가자·발언·투표·집계·모더레이션이 FK cascade로 함께 삭제된다. 즉 **삭제 단위는 세션**이다.

## 2. 보관기간 (사실 + [검토 필요])

- 세션별 보관기간은 `privacy_settings.retentionDays`에 저장된다. **파일럿 기본값 30일.**
- 보관기간은 워크숍 종료(마지막 스냅샷 발행) 시점 기준으로 계산하는 것을 권장한다.
- [검토 필요] PIPA상 보관기간 상한/최소 보존 의무(예: 특정 기록의 법정 보존), 목적 달성 후 지체 없는 파기 원칙의 구체 적용.

### 2-1. 전사 텍스트 보관기간 (제안 — 법무 검토 대상)

- **전사 텍스트(`transcript_segments` / `transcript_insights`)의 기본 보관기간은 7일**로, `retentionDays`(기본 30일)보다 **짧게** 잡는다.
- 근거: `docs/transcript-architecture.md` §4 — 제품의 원자료는 참가자가 스스로 제출한 `statements`이며, 전사는 그 요약을 만들기 위한 **중간 산출물**이다. 중간 산출물이 원자료보다 오래 남을 이유가 없다.
- 요약·승격된 `statements`는 전사 삭제 후에도 남는다(사람이 승인한 결과물). 따라서 전사 삭제가 납품물을 훼손하지 않는다.
- [검토 필요] 7일이라는 값의 법적 적정성, 음성 기반 개인정보의 별도 보존 요건 유무. (`transcript-architecture.md` §8 남은 결정 항목과 동일)

### 2-2. 원음성 파일 (현장 기기) — 24시간 자동 삭제

- 원음성은 **서비스 서버에 저장되지 않는다.** DB 스키마에 오디오 경로·파일명 컬럼 자체가 없다(`0017_transcript_consent.sql`).
- 현장 전사 기기의 임시 wav 파일은 **워크숍 종료 후 24시간 내 자동 삭제**한다.
- **삭제 증빙**: 자동 삭제 스크립트가 텍스트 로그(세션 ID·파일 개수·삭제 시각·실행 호스트)를 남기고, 이 로그를 워크숍 운영 기록과 함께 보관한다. 로그에는 파일명·경로를 남기지 않는다(내용 추론 방지).
- [검토 필요] 자동 삭제 실패 시 통지·재시도 절차, 기기 분실·압수 시나리오 대응.

## 3. 삭제 절차 (사실 + 운영 규칙)

현재 MVP에는 자동 만료·일괄 파기 배치가 포함되어 있지 않다(수동 운영). 따라서 다음 운영 규칙으로 보완한다:

1. [ ] 각 세션 종료 시, 보관기간(`retentionDays`)에 따른 **삭제 예정일을 운영 캘린더에 등록**한다.
2. [ ] 삭제 예정일에 해당 **세션을 삭제**하면 FK cascade로 참가자·발언·투표·집계·모더레이션·입장키가 함께 삭제된다.
3. [ ] 삭제 실행 후 **삭제 완료 기록**(세션 ID·삭제일·실행자)을 남긴다.
   - [ ] 녹음 세션이면 **전사 텍스트 삭제(종료 +7일)** 와 **현장 기기 원음성 삭제(종료 +24h)** 를 각각 별도 일정으로 등록하고, 실행 후 삭제 로그를 남긴다.
4. [ ] [검토 필요] Neon 등 DB 백업·복제본에서의 파기 시점(백업 보존주기와 삭제 정책의 정합성).
5. [ ] [검토 필요] `action_ledger` 등 감사 로그를 세션과 함께 지울지, 별도 보존할지의 정책 판단.

> 개선 후보(향후): `retentionDays` 만료 세션을 스캔·삭제하는 배치. MVP에서는 수동 절차로 대체하고, 파일럿 볼륨(5건 이내)에서 감당한다.

## 4. 접근 권한 (사실)

제품이 RLS(Row Level Security)로 강제하는 접근 통제:

- **개인 투표 원자료**(`statement_votes`)의 raw 조회는 **admin 외 전면 차단.** 운영자(instructor)·참가자도 개인 표를 직접 조회할 수 없고, 집계는 `delib_vote_tally` 보안 함수로만 노출된다. → 권위자의 개인 표 추적을 구조적으로 차단.
- 발언·라운드·그룹·스냅샷은 **세션 멤버만 열람**, 쓰기는 역할별로 제한(instructor 관리, participant 제출).
- **전사 데이터(`transcript_*`)는 운영자(admin/instructor/assistant) 전용 열람**이며 참가자는 RLS로 차단된다. 쓰기는 서버 경로(instructor 이상)만 가능하다(`0017_transcript_consent.sql`).
- 결과 리포트 export(`/api/export/delib`)는 **operator 전용**(LIVEOPS_OPERATOR_KEY 설정 시 미들웨어+라우트 2차 검증)이며, export 행위는 `action_ledger`에 기록되어 무추적 반출을 막는다.

접근 권한 운영 규칙:
- [ ] operator key는 퍼실리테이터·운영 지원에게만 배포하고, 워크숍 종료 후 회수/교체를 [검토 필요] 주기로 관리.
- [ ] [검토 필요] admin 역할 부여 대상·감사 주기.
