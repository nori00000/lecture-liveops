# 퍼실리테이터 런북 — 숙의 워크숍 현장 운영

> 대상: 이 도구로 30~80명 규모의 논쟁형 워크숍을 진행하는 퍼실리테이터·운영 지원 인력.
> 목적: 사전 준비부터 종료·납품까지 현장에서 그대로 따라 하는 실전 체크리스트.
> 제품 규칙 근거: `docs/PRODUCT-PLAN-v2.md` §7(거버넌스) — 이 문서는 그 규칙을 현장 동작으로 옮긴 것이다.

핵심 원칙 (외우고 시작): **AI/도구는 결론을 내지 않는다. 사람의 의견·투표가 원자료이고, 도구는 그것을 절차 증빙과 함께 정리·납품할 뿐이다.**

---

## 0. 역할·화면 개요

| 화면 | 경로 | 누가 본다 |
|---|---|---|
| 운영자 콘솔 | `/workshops/{sessionId}/console` | 퍼실리테이터·운영 지원(operator 로그인) |
| 워크숍 설정 | `/workshops/{sessionId}/settings` | 퍼실리테이터(세션 시작 전) |
| 프로젝터 결과판 | `/workshops/{sessionId}/projector` | 전체 스크린(참가자 공용) |
| 참가자 입장 | `/p/enter` → 대시보드 | 참가자(access key 1회 입력) |
| 결과 리포트 | `/api/export/delib?sessionId=…&format=md\|html\|xlsx` | operator 전용 |

- 개인별 투표 원자료는 **운영자에게도 노출되지 않는다**(집계·플래그만). 권위자(목회자·교사·상급자)가 개인을 추적할 구조적 여지를 남기지 않는다.
- 리포트에는 개인 표가 담기지 않는다 — 집계·원 발언·절차 로그만.

## 1. 사전 준비 (D-3 ~ 당일 1시간 전)

### 1-1. 시나리오·라운드 설계 (D-3)
- [ ] 논제 1문장 확정 (예: "우리 동네 도서관 운영 시간, 어떻게 정할까").
- [ ] 라운드 구성 확정: 보통 **오프닝(전체) → 분임 토론(그룹) → 전체 종합**. 라운드는 한 번에 하나만 활성화되며, 새 라운드를 열면 이전 라운드는 자동으로 닫히고 그 라운드에는 더 이상 발언을 제출할 수 없다. **각 라운드의 발언·투표는 그 라운드가 열려 있는 동안 받는다.**
- [ ] 분임(그룹) 수·인원 확정 (30명이면 4~5조, 80명이면 6~8조 권장).

### 1-2. 프라이버시 사전 합의 설정 (필수 게이트, D-1)
> 이 설정을 확정하지 않으면 **서버가 워크숍 시작을 거부한다.** UI 체크가 아니라 서버 규칙이다.
- [ ] `/workshops/{id}/settings`에서 다음을 확정:
  - **익명/기명 모드**. 단 **참가자 N<12면 익명 모드는 비활성**된다 — 소규모 익명은 사실상 익명이 아니기 때문. 소규모는 기명 또는 무기록 토의로 안내.
  - **공개범위**(참가자 공개 / 운영자 전용 / 공개).
  - **보관기간**(일 단위). `docs/data-retention-policy.md` 기준으로 정한다.
  - **사전 합의 확인 체크**(consent) — 참가자 고지 완료 후에만 켠다.
- [ ] **미성년자 세션**이면 미성년 세션 플래그 + 법정대리인 동의 문구·수집 절차를 켠다. 단순 체크박스가 아니라 동의 확보 플로우를 거쳐야 서버가 통과시킨다. (⚠️ 법적 요건은 `docs/privacy-template.md`의 경고 참조 — 전문가 검토 전제)

### 1-3. 접속·기기 점검 (당일 T-60)
- [ ] dev/운영 서버 헬스 확인: `/api/health` 가 `ok:true`.
- [ ] (시연·리허설용) 데모 데이터가 필요하면 `npm run seed:demo` — 결정론적 데모 워크숍 1개를 만들고 콘솔·프로젝터·리포트 접속 정보를 출력한다. 시딩은 다량의 운영자 호출을 하므로 dev 서버를 `LIVEOPS_RATE_LIMIT_DISABLE=1 npm run dev` 로 띄운 뒤 실행하는 것을 권장.
- [ ] 콘솔·프로젝터를 각각 다른 창/기기에서 열어 둔다(운영자 기기 ≠ 프로젝터 기기 권장).
- [ ] 참가자 access key / QR 배포물 준비. **QR은 `/p/enter`로 연결**하고, key는 콘솔에서 발급한다.
- [ ] 프로젝터 폴링은 2~5초, 개인 폰 폴링은 10~15초 — 대량 접속 시 부하 여유를 둔다.
- [ ] 네트워크 폴백 준비: 1-4 참조.

### 1-4. 장애 폴백 사전 준비
- [ ] **종이 대리 입력 양식** 인쇄(발언 1건 = 1칸, 그룹 표기). 폰 없는 참가자·네트워크 장애 대비.
- [ ] **폰 없는 참가자용 코드** 여분 발급.
- [ ] 운영자용 보조 회선(테더링) 1개.

## 2. 진행 (본 세션)

### 2-1. 오프닝
- [ ] 프라이버시 고지를 **구두로 1분** 안내(무엇을 수집·왜·언제 삭제·익명 범위). `docs/privacy-template.md` 요약을 읽는다.
- [ ] QR/access key로 입장 시연 1회. 참가자 1~2명이 실제로 들어오는지 확인.
- [ ] 오프닝 라운드에서 논제·규칙(존중·발언권·소수의견 보호)을 공유.
- [ ] **프리벙킹 카드 5~10분** (아래 2-1b) — 발언이 시작되기 **전에** 한다.

### 2-1b. 프리벙킹 — "이런 어법이 나올 수 있습니다" (전원 대상, 5~10분)

**왜 이걸 먼저 하는가**: 발언 *후에* 개인을 지적하면 방어적으로 자기 입장을 더 굳힌다. 발언 *전에* 전원에게 미리 말해두면 방어 대상이 없어 저항이 없다(사전 책무성 원리). 이 도구는 **누가 오류를 범했는지 판정하지 않는다** — 참가자가 스스로 알아차리게 돕는 것이 전부다.

프로젝터에 띄우고 진행자가 읽는다. **특정 진영의 어법만 예시로 들지 않는다**(중립 표현으로 작성 — 아래는 주제 무관 예시).

| 카드 | 이렇게 들립니다 | 대신 |
|---|---|---|
| **① 근거 없는 단정** | "그건 원래 다 그래요" / "당연히 ~죠" | "제 경험으로는 ~" 또는 "이 자료에 따르면 ~" |
| **② 극단 사례로 일반화** | "한 번 이런 일이 있었으니 전부 그렇다" | "제가 본 사례는 ~인데, 전체가 그런지는 모르겠습니다" |
| **③ 상대 주장 단순화** | 상대가 말하지 않은 극단 버전을 반박 | "제가 이해한 게 맞나요? ~라는 말씀이신가요?" |
| **④ 두 개 선택지만 있는 것처럼** | "찬성 아니면 반대죠" | "제3의 안이 있을까요?" |
| **⑤ 사람 vs 주장 혼동** | "그 사람이 그러니까" | "그 주장의 근거가 ~인 점이 걸립니다" |

**⚠️ 무기화 방지 (반드시 함께 안내)**: "오늘 배운 이 말들을 **상대를 지적하는 무기로 쓰지 않기로 합시다.** '그거 허수아비네요'라고 하는 순간 토론이 아니라 판정이 됩니다. 이 카드는 **자기 발언을 돌아보는 용도**입니다."

**앱과 연결**: 의견 제출 시 `근거: 경험 / 자료·출처 / 추정`을 고르게 되어 있다. "추정을 고르는 건 부끄러운 게 아닙니다 — **추정을 추정이라고 밝히는 게 정확한 것**"이라고 안내한다.

- [ ] 라운드 전환마다 **30초 리마인더**(효과가 시간이 지나면 옅어진다): "아까 카드 기억하시죠? 특히 ②번, 한 사례로 전체를 말하고 있지 않은지."

### 2-2. 라운드 운영 루프 (라운드마다 반복)
1. [ ] 콘솔에서 해당 라운드를 연다(이전 라운드는 자동으로 닫힌다).
2. [ ] **발언 유도**: 그룹별로 의견을 받는다. 참가자가 직접 제출하거나, 종이/구두 의견은 운영자가 **대리 입력**한다.
3. [ ] **투표 타이밍**: 발언이 어느 정도 모이면 투표를 연다. 찬성/반대/유보 3택. 1인 1표(변경 가능, 서버가 최종 강제).
4. [ ] **소그룹 ↔ 전체 전환**: 분임(breakout)에서는 그룹 내 논의, 전체(plenary)에서는 종합. 전환은 새 라운드를 여는 것으로 처리.
5. [ ] 라운드 종료 전 발언·투표가 충분한지 콘솔의 진행률(voteProgress)로 확인.

### 2-3. 결과판 발행
- [ ] 종합 시점에 **스냅샷 계산 → 발행**. 발행해야 프로젝터 결과판에 공개된다.
- [ ] 결과판은 **합의(consensus)·쟁점(divisive)·소수의견(minority)** 세 축으로 읽는다.
  - 합의: 한쪽으로 강하게 쏠린 발언.
  - 쟁점: 찬반이 팽팽한 발언 — 추가 토의 후보.
  - 소수의견: 전체 다수와 반대 방향인 발언 — **"지목"이 아니라 "소수 관점 요약" 카드**로 표기(비율만, 인원 미표기 옵션).
- [ ] **k-익명 억제**: 표가 너무 적은 발언(소표본)은 수치가 마스킹되어 결과판·랭킹에서 빠진다. 이는 개인 표 역추론을 막기 위한 정상 동작이다. 참가자가 물으면 "표가 적어 개인이 드러날 수 있어 수치를 가렸다"고 안내.

## 3. 민감 상황 대응

| 상황 | 대응 |
|---|---|
| **익명인데 인원이 적다(N<12)** | 익명 모드가 비활성됨을 미리 안내. "이 인원에서 익명은 지켜지지 않는다"고 솔직히 말하고 기명 또는 무기록 토의로 전환. |
| **부적절·공격적 발언** | 콘솔 모더레이션 큐에서 신고/숨김/보류. 조치는 감사 로그(moderation_events)에 남는다. 숨긴 발언은 집계에서 제외되지만 기록은 보존. |
| **프리벙킹 용어가 공격 무기가 됨** ("그거 허수아비잖아요") | 즉시 개입: "그 지적은 잠시 멈추고, **상대 주장을 먼저 자기 말로 요약**해 주시겠어요?" 카드는 자기 점검용이라는 오프닝 약속을 다시 상기. 반복되면 해당 라운드는 카드 언급 없이 진행. |
| **"추정" 태그를 아무도 안 고르거나 전부 고름** | 분포가 한쪽으로 쏠리면 변별력이 없다. "확실한 근거가 있는 것만 자료로 골라달라"고 한 번 안내. 그래도 쏠리면 이 세션의 근거 분포는 리포트에서 참고용으로만 다룬다. |
| **권위자의 압박(목회자·교사·상급자)** | 개인 투표 원자료는 운영자에게도 안 보인다는 사실을 **공개적으로 고지**해 심리적 안전을 확보. 권위자가 개인 표를 요구하면 "구조적으로 조회 불가"라고 답한다. |
| **소수의견 보호** | 소수 관점은 "누가"가 아니라 "무엇"으로 카드화. 인원 대신 비율로만 표기. 소표본은 k-익명으로 자동 보호됨. |
| **특정인이 발언 독점** | 그룹 라운드로 분산, 발언권 순환. 필요 시 종이 제출로 조용한 참가자 의견 흡수. |

## 4. 종료·납품

- [ ] 마지막 종합 라운드에서 최종 스냅샷 발행(결과 스냅샷 = 절차 증빙의 확정 시점).
- [ ] **리포트 발행**: `/api/export/delib?sessionId=…&format=md|html|xlsx`.
  - `md`: 편집·요약용. `html`: 즉시 열람·공유용. `xlsx`: 표·집계 검토용.
  - 리포트에는 원 발언·집계·절차 로그가 연결된다. 개인 표는 담기지 않는다.
- [ ] 발주처/주최에 리포트 납품 + 후속(NPS·재인용 여부) 청취.
- [ ] 보관기간·삭제 일정 재확인(`docs/data-retention-policy.md`). 약정한 삭제일을 캘린더에 등록.

## 5. 장애 폴백 상세

| 장애 | 즉시 조치 |
|---|---|
| **네트워크 끊김** | 폴백 회선으로 전환. 복구 지연 시 종이 대리 입력으로 발언·투표를 수집하고, 복구 후 운영자가 일괄 입력. |
| **참가자 폰 없음/미숙** | 여분 코드 발급 또는 종이 제출 → 운영자 대리 입력. 폰 없는 참가자를 배제하지 않는다. |
| **rate limit(429) 발생** | 대량 동시 제출 시 발생 가능. 잠시 후 재시도(서버가 retry-after 안내). 투표를 그룹별로 시차를 두고 연다. |
| **프로젝터 오류** | 결과판은 프로젝터 전용이 아니다 — 운영자 콘솔에서도 스냅샷을 확인해 구두 공유 가능. |
| **잘못된 발언 제출/오타** | 모더레이션으로 숨김 처리(삭제가 아니라 감사 보존). 필요 시 정정 발언을 새로 제출. |

## 6. 원클릭 체크 요약 (당일 프린트용)

- [ ] 프라이버시 설정 확정(합의 체크 ON) → 서버가 시작 허용
- [ ] N<12면 익명 OFF 안내
- [ ] QR/키 배포 + 입장 시연 1회
- [ ] **프리벙킹 카드 5~10분 (발언 전!) + 무기화 방지 약속**
- [ ] 라운드 순서대로: 열기 → 발언 → 투표 → 종합 (전환마다 카드 30초 리마인더)
- [ ] 스냅샷 계산·발행 → 결과판 공개
- [ ] 민감 발언은 모더레이션 큐로
- [ ] 리포트 3형식 발행·납품
- [ ] 삭제 일정 등록
