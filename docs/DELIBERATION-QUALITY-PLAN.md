# 숙의 품질 지원 — 기능 기획 v2

> 2026-07-22. v1은 critic 적대 검증에서 **RECONSIDER** 판정(근거 취사선택·원 요청 회피·거버넌스 자기모순). 이 v2는 9개 최소 수정 조건을 반영한 재작성.
> 근거: opus 학술 딥리서치 + Codex 구현 리서치(독립 병렬) + critic 적대 검증.

## 0. 문제와 전제

**사용자 원 문제**: "사람들이 사실 확인 없이 단정하고, 논리와 맥락을 뛰어넘는다."

**전제 정정 (v1 오류)**: v1은 Wason 선택과제(개인 10%→집단 70%)를 들어 "집단은 이미 오류를 스스로 잡는다"고 낙관했다. 그러나 Wason은 **정답이 있는 논리 퍼즐**이고 우리 워크숍은 **정답이 없는 가치 논쟁**이다. 전이는 미검증이며 반대 증거도 있다(집단 극화 — Sunstein; hidden profile — Stasser & Titus).
→ **"집단이 알아서 잡는다"를 이유로 오류 대응을 면제할 수 없다.** 우리가 실시간 오류 판정을 하지 않는 이유는 §1의 탐지 성능·피드백 해악이지 이 낙관이 아니다.

## 1. 만들지 않는 것 (근거가 정면으로 반대)

| 안 만드는 것 | 근거 |
|---|---|
| **참가자에게 실시간 논리 오류 판정 표시** — **금지(정밀도 기준 없음)** | 세분류 오류 탐지 최고 **F1 0.14~0.20**(MAFALDA, NAACL 2024). 야생 데이터에선 **인간 주석자 간 일치도조차 낮다**(ArgMining 2023) |
| 〃 | 피드백 메타분석 607 효과크기·N=23,663 중 **약 38%가 성과 저하**, 주의가 자아로 향할수록 악화(Kluger & DeNisi 1996). *단 이는 성과 피드백 전반의 결과이고 숙의 대화 품질로의 전이는 미검증* |
| 〃 | LLM 퍼실리테이터 RCT(N=1,475, arXiv 2508.08242): 직접 호명이 불편감 유발, **최종 결정 품질 개선 0**(31%, p=0.42) |
| 〃 | **AI 페널티**(사전등록 N=1,850): AI 진행 고지만으로 참여 의사·품질 평가 하락 |
| **집단사고 탐지** | 구성 개념의 실증 근거 부족(Mullen et al. 1994 메타가 핵심 예측 미지지) |
| **침묵의 나선 탐지** | 상관 **r=.05**(Glynn et al. 1997 메타) |
| **독성 점수 자동 경고** | Perspective API 비영어 정확도가 영어보다 낮고 **정체성 단어 언급만으로 점수 상승**이 반복 문서화 → 소수자 이슈에서 역방향 오작동 *(정확도 수치는 출처 미확보 — 정성 근거로만 사용)* |
| **개인·진영 라벨** | 정치적 비대칭(분노를 표현하는 피해자·소수자 발언이 더 자주 flag) → 절차 중립성 파괴 |

**성공한 시스템의 공통점**: Stanford ADP·Habermas Machine·Polis — 전부 **판정이 아니라 구조화·집약·가시화**. 실배치되어 살아남은 것 중 참가자에게 실시간 오류를 판정하는 시스템은 **하나도 없다**.

## 2. 만드는 것 — 원 문제 직격 순

### Q1. 참가자 자기 태깅 (근거 유형 선택) ★ MVP 후보 1
발언 제출 폼에 `이 주장의 근거: 경험 / 자료·출처 / 추정`을 **참가자 본인이 선택**.
- **왜 이게 원 문제의 답인가**: "미검증 단정"이 **판정 없이** 가시화된다. "추정" 비율이 곧 미검증 주장의 비율이고, 라운드·그룹별로 집계된다
- **왜 안전한가**: AI 판정 0 → 오탐 0. 자기 귀속이라 self-level 피드백이 아님(Kluger & DeNisi 회피). §1이 승인한 "구조화" 범주
- **구현**: `statements`에 `evidence_kind` 추가(마이그레이션 1개), 제출 UI 셀렉트, 집계는 기존 metrics에 필드 추가. **LLM·외부 API 0**
- **한계**: 자기보고라 부정확할 수 있다(자기 주장을 "자료"로 과대표기). 그래도 **틀린 AI 판정보다 낫다** — 오귀속의 주체가 본인이다

### Q2. 사후 리포트의 쟁점·미검증 주장 정리 ★ MVP 후보 2 (가격 방어 핵심)
세션 종료 후 배치로 **납품 리포트에 "검토가 필요한 주장" 섹션**을 만들고, **퍼실리테이터가 승인한 것만** 실린다.
- **왜 이게 v1에서 빠진 게 회피였나**: §1의 반대 근거가 여기선 거의 무력화된다 — 실시간 오탐 비용 없음(납품 전 사람 검토), 즉시 self-level 피드백 아님, 청중 앞 노출 없음, 지연 허용이라 로컬 모델 여유. 그리고 **경쟁 격차를 실제로 벌리는 건 납품물에 실리는 것뿐**인데 v1은 그걸 버렸다
- **근거**: check-worthy claim은 세 기술 중 가장 성숙(CLEF CheckThat! 매년 벤치마크), ClaimBuster **상위 100문장 정밀도 0.96** — 전수가 아니라 **랭킹 상위 소수만** 제시하면 실용적
- **게이트**: 정밀도 70% 기준(사후·사람 검토 전제라 실시간보다 낮게). **퍼실리테이터 기각률을 §5 지표로 실측**
- **구현**: 스냅샷과 분리된 비동기 액션(`delib.compute_ai_observations`), 실패 시 리포트는 AI 섹션 없이 정상 발행

### Q3. 사전 프리벙킹 카드 (개발 산출물 아님 — 런북)
세션 도입부 5~10분 **전원 대상** "오늘 이런 어법이 나올 수 있습니다" 카드 + **라운드 전환마다 30초 리마인더**(접종 효과 감쇠 대응).
- **근거와 한계**: 접종이론 메타 d≈0.43(Banas & Rains 2010) — **단 오정보 판별 맥락이며 "자기 발언 교정"으로의 전이는 미검증**. 타이밍 원리(사전 책무성은 편향 감소, 사후는 방어적 보강 — Lerner & Tetlock 1999)와는 일치
- **부작용 대응(v1 누락)**: 참가자가 배운 용어를 상대 공격에 쓰는 **무기화** 위험 → 런북에 "카드 어법을 상대 지적에 쓰지 않기" 규칙 + 발생 시 진행자 스크립트
- **카드 내용 검수**: 예시가 한쪽 진영 어법으로 편중되면 절차 중립성이 깨진다 → 카드 세트는 주제 중립 표현으로 작성하고 파일럿마다 재검토
- **구현**: 코드 변경 없음(런북 + 프로젝터 슬라이드)

### Q4. 기존 참여 지표 노출 (신규 개발 최소)
- **v1의 오류 정정**: v1은 이 항목에 `d=0.61`을 붙였으나 그 수치는 **LLM이 대화에 실시간 개입하는 설계**에서 나온 것이고 우리 설계(진행자 대시보드)와 다르다. Stanford ADP 인용도 마찬가지(ADP는 참가자 대면 발언권 관리). **→ 이 항목의 효과크기 근거는 없다.** 정직한 표기: `[근거 없음 — 데이터 이미 보유, 오탐 0]`
- **실제 신규분은 거의 없다**: 라운드별 참여율(`console-view` voteProgress)과 그룹 간 편차(`metrics.ts` groupDeviation)는 **이미 구현돼 있다**. 남는 건 화면 노출과 런북 연결
- **개인 단위 표시 금지(거버넌스 자기모순 정정)**: "미발언 참가자" 개인 표시는 §7-2(개인 추적 구조적 차단)를 뚫는다. 그룹은 물리적 테이블이라 익명 핸들도 좌석 대조로 실명화된다 → **그룹 단위 집계만**, 그룹 크기 k(=3) 미만이면 억제
- **지표명 정정**: `발언 균등도`가 아니라 **`앱 제출 분포`** — 오프라인에서 실제 대화는 구두로 일어나고 우리가 재는 건 제출 텍스트뿐이다. 화면에 "구두 발언은 측정되지 않음" 상시 고지. **대리입력이 있는 라운드는 분포 지표 억제**(대리입력 시 저자 미지정이면 조용한 참가자가 영구 미제출자로 잡힘)

### Q5. 공통지반 요약 (P2 이후)
"지금까지의 합의점 / 남은 이견"을 세션 중간·끝에 제시. **참가자 대면 제시가 정당화되는 유일하게 근거가 강한 AI 산출물**(Habermas Machine, Science 386:eadq2852, N=5,734).
- **v1 과장 정정**: v1은 "이미 절반 가지고 있다"고 했으나, 우리가 가진 consensus/divisive 랭킹·GIC는 **투표 산술값이지 자연어 합의문이 아니다**. Habermas Machine의 효과가 나온 부분은 **LLM이 쓴 자연어 합의문**이다 → 우리가 가진 건 절반이 아니라 **원료**
- **게이트**: 합의문 초안에 대한 **퍼실리테이터 수정률 ≤ 50%**, 초과 시 보류. 로컬 모델(EXAONE)의 한국어 합의문 품질이 동급이라는 근거는 없으므로 파일럿에서 실측

### Q6. 퍼실리테이터 전용 실시간 신호 — **현재 계획 없음**
v1은 "한국어 오탐률 게이트"를 걸었으나, 그 게이트는 (a) 데이터 없음(파일럿 0건), (b) **녹취는 PRODUCT-PLAN §3에서 명시적 제외**라 순환 의존, (c) 제3자 라벨러에게 참가자 발언을 보여주는 프라이버시 근거 부재, (d) 1인 기준 40~60시간 — 사실상 "안 만든다"의 완곡어법이었다.
**재검토 조건**: 유료 파일럿 5건 누적 + 전사 파이프라인 가동 + 라벨링 예산·동의 설계 확보. 그 전까지 로드맵에 없다.

## 3. 아키텍처

- **`compute_snapshot`에 LLM을 붙이지 않는다**(v1 오류 정정): `computeSnapshot`은 cron 배치가 아니라 **운영자가 콘솔에서 호출하는 동기 액션**이다. 여기에 LLM을 넣으면 현장에서 결과판을 띄우는 순간 진행이 멈춘다
- **별도 비동기 경로**: `delib.compute_ai_observations` 신규 액션. 실패·타임아웃 시 **결과판과 리포트는 AI 섹션 없이 정상 발행**(전사 박스와 동일 원칙 — AI를 크리티컬 패스에 올리지 않는다)
- **저장**: `round_ai_observations` 별도 테이블(moderation_events와 분리 — 품질 피드백이 제재로 보이면 안 됨)
- **모델**: 현장 실시간에는 로컬 모델을 쓰지 않는다(m4-studio 의존은 워크숍을 사용자 집 서버에 묶는 단일 장애점). **세션 후 처리에만** 로컬 EXAONE, 외부 API는 `offsiteProcessing` 동의 세션 한정

## 4. 선행조건·kill 기준

- **P1 선행조건: `PRODUCT-PLAN-v2.md` §6 게이트 1 통과** (v1은 "선행조건 없음"으로 상위 기획서의 유일한 자원 통제를 무력화했다)
- **kill 기준 (사전등록)**:
  1. 파일럿 3건 누적에서 **퍼실리테이터가 Q2 "검토 필요 주장" 후보를 실제로 납품물에 채택한 건수 0** → Q2 폐기
  2. Q5 합의문 초안 **수정률 > 50%** → Q5 보류
  3. Q1 "추정" 태그 선택률이 **5% 미만**(아무도 안 씀) 또는 **80% 초과**(변별력 없음) → Q1 재설계

## 5. 측정 지표 (사전등록)

| 지표 | 목표 | 판정 |
|---|---|---|

## 6. 로드맵

현재 구현 상태(2026-07-22): Q1/Q2/Q3/Q4 완료. Q5는 리포트의 품질 게이트(Q1 추정 태그 비율, Q2 후보 채택률)로 P2 실측을 남길 수 있게 준비했지만, 자연어 공통지반 요약 생성은 파일럿 수정률 게이트 전까지 보류한다.

| 단계 | 내용 | 선행조건 |
|---|---|---|
| **P1** | ✅ Q1 자기 태깅 + Q3 프리벙킹(런북) | **게이트 1 통과** |
| **P2** | ✅ Q2 사후 리포트 쟁점 정리 + Q4 기존 지표 노출(그룹 단위) | P1 파일럿 1건 |
| **P3** | ⏸ Q5 공통지반 요약 | P2 실측 + 수정률 게이트 |
| 없음 | Q6 실시간 신호 / 참가자 대면 오류 표시 | **계획 없음** |

## 7. v1에서 삭제한 것

- **학술 A/B("참가자 대면 vs 퍼실리테이터 대면" RCT 내장)**: 이를 하려면 §1이 유해하다고 판정한 arm을 유료 고객 워크숍에서 실제로 돌려야 한다. IRB 없고 고지·동의 설계도 없다. **우리는 수행하지 않는다** — 학계 협력자가 있을 때만 재검토
- Q4의 개인 단위 미발언자 표시, d=0.61·Stanford ADP 인용, "효과크기 최대" 주장, Q6의 게이트 위장
